# Viva Mais media

Brand, videos, and presentations for Viva Mais. Standalone repo linked to the product monorepo: `pnpm run sync:monorepo` fetches `main` into `.monorepo/` (gitignored, pinned in `monorepo.lock`), regenerates brand colours from `packages/theme`, and rebuilds the screen library. `pnpm run monorepo:status` says whether the pin is behind.

## Layout

- `brand/` — single source of truth for the brand: `tokens.json` (palette, gradients, fonts, radii, eases), generated `tokens.css`, `app-ui.css` (app tokens, only for mimicking app UI), `fonts/`, `logos/`, `frame.md` (design + motion spec), `formats.json`.
- `screens/` — app screens rendered from the real app source in `.monorepo`, with fixtures; output in `screens/dist` (markup, CSS, stills, gallery). Read `screens/README.md` before adding or using a screen.
- `assets/` — shared media library (app illustrations and icons, doctor portraits, personas, footage). One copy each; videos list what they use in `assets.json`.
- `videos/` — HyperFrames projects: `ads/`, `tutorials/`, `clips/`, plus `kit/`, `capture/`, `templates/`. Read `videos/CLAUDE.md` before touching any video.
- `presentations/` — static HTML decks (apresentação + proposta), not HyperFrames. Read `presentations/README.md` before editing a deck.
- `studio/` — Viva Mais Studio, the brand tool (Vite + React + Tailwind v4, own `package.json`): `pnpm run studio`. `src/ui/` is Toolcraft's UI layer vendored (MIT), rethemed in `src/styles.css`; never edit it, our code goes in `shell/`, `pages/`, `tokens/`. Tokens page reads `.monorepo/packages/theme/tokens.json`; UI web renders the real `@vivamais/web-ui` stories in an isolated iframe (`frame.html`), resolved through the `.monorepo/packages/web-ui/node_modules` symlink that `predev` creates; UI mobile shows `screens/dist` (component sheets `screens/mobile/kit-*.screen.tsx` plus app screens), so run `pnpm run screens` first.
- `posts/` — static pieces, one JSON doc each (layer tree, base size, per-format overrides), edited in the Studio under Biblioteca: one catalog grouped by `style` (estilo visual, list in `studio/src/posts/catalog.ts`), filtered by format and `topics`; selected 4:5 pieces join into a new carousel. Posts export feed/story/square; sequences are carrossel or panorâmico; covers are IG highlights and banners. Colours in posts are token refs (`{violet.500}`, `{primary}`, alpha as `{violet.500}/60`) resolved from `brand/tokens.json` at render, so they follow the monorepo theme; write refs, not hex. Saved by the Studio dev server; `posts/export/` holds PNGs (gitignored). Paper pieces come in with `node studio/scripts/paper-import.mjs` (Paper JSX → layers, images to `assets/posts/paper/`). Phone mockups use real `screens/dist` shots so they track the monorepo; photos of a phone in hand get a "Tela na foto" layer (real screen projected onto the phone, fingers masked) from `assets/posts/photo-screens.json`, generated by `python3 tools/photo-screens.py <photo>` for photos with a blank white screen. Export needs `pnpm run studio` running. In the Studio, ⌘C on a selected frame or layer copies a reference `vm:<doc>/<frame>[/<layer>]`; when one appears in a request, run `pnpm run ref "<text>"` (add `--json` for the raw node) to see exactly which piece, frame and layer it means before editing `posts/<doc>.json`.
- `tools/` — repo scripts behind the root `package.json`.

Package manager: the root, `studio/` and `remotion/` are one pnpm workspace (`pnpm install` at the root, scripts as `pnpm run <script> <args>`; pnpm passes a literal `--` through, so leave it out). Each package declares what it imports. Video folders are standalone HyperFrames projects outside the workspace and keep `npm run` / `npx` inside their own folder.

## Making videos

Use the `/video` skill for any video request: it runs the `video-director` → parallel `scene-builder` → `video-reviewer` agents (`.claude/agents/`) and renders. House taste: `videos/STYLE.md`. Catalog: `pnpm run list`.

## Brand rules

- Colours in `brand/tokens.json` are generated from the monorepo theme by `pnpm run sync:monorepo`; never hand-edit `color`. Brand-only colours go in `colorLocal`. Change a gradient, font, or radius in `brand/tokens.json`, then `pnpm run sync:brand`. Decks read `--vm-*` through `shared/deck.css`; videos link `assets/brand/tokens.css`.
- Violet dominates, spark is the secondary accent, iris and azure are supporting tones, never fills; light cards use `--vm-tile` with no border; token names match the product monorepo; solid fills over gradients. Full spec in `brand/frame.md`.
- Logos come from `brand/logos/`; never redraw or recolor the mark.

## Sync

`pnpm run sync` copies `brand/` and each video's `assets.json` files into every video and into `presentations/assets/brand/`, and fills `<!-- screen:id state -->` markers from `screens/dist`. The copies are gitignored, so a fresh clone or a brand/library edit needs `pnpm run sync` before preview, render, or export. Add a shared file to `assets/`, map it in the video's `assets.json`, sync; video-specific media stays inside the video.

## Checks

- Videos: `pnpm run check` (all) or `pnpm run check <slug>`.
- Decks: `pnpm run deck:export` and compare against the previous export before calling a deck change done.
- Memory pressure: never run capture, preview, and render at the same time; `pkill -f chrome-headless-shell` when puppeteer stalls.
